# Immutable worker identity and graceful HTTP shutdown

Reviewed and implemented 2026-09-07.

A reproduced path-replacement bug returned changed computation bytes with the original startup digest. Startup now reads the executable once into a sealed Linux memfd, hashes those bytes, checks its version and runs only that descriptor. Admission and accepted/completed/failed counters share a condition lock. /live, /ready and /metrics expose lifecycle state. SIGTERM/SIGINT reject new work, drain accepted requests up to a deadline, then kill worker process groups and reap children. Actual HTTP tests cover graceful and forced drain, CLI SIGTERM, malformed workers and executable replacement.

## Why this scope

Backend/cloud infrastructure: concurrency admission, readiness, graceful termination, operational counters and reproducible process identity. [Dated official hiring and release review](market-review-20260907.md). Other portfolio projects already cover distributed queues and cloud provisioning; this change addresses defects at this repository’s own boundary. No additional framework is required.

## Tradeoffs and limits

This is a Linux x86_64 reference service. JSON /metrics is a small low-cardinality operational endpoint, not a Prometheus exporter. The server counts computed HTTP outcomes; it cannot prove the peer consumed a response. Readiness/drain is not a Kubernetes deployment or production SLA. Trusted scripts are test fixtures; the shipped worker is a native ELF.

These are local CPU/Linux experiments with test-owned faults. No production traffic, cloud deployment, GPU execution, user count or service-level availability is inferred. Timing campaigns retain environment, raw samples and their original comparison method; this maintenance does not claim a performance improvement.
